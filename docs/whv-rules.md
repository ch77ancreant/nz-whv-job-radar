# Phase 2：台灣 WHV 職缺初篩規則

適用範圍：本專案的 SEEK 職缺文字初篩，不是簽證申請審核或法律意見。
規則版本 `tw-whv-1.0`；官方條件查核日期 **2026-09-23**。

## 官方條件與程式判斷要分開

[Immigration New Zealand：Taiwan Working Holiday Visa](https://www.immigration.govt.nz/visas/taiwan-working-holiday-visa/)
目前列出可從事臨時工作、同一雇主最多三個月，且不得從事永久工作。

本程式只把這幾項與職缺廣告交叉檢查，不驗證個人的簽證是否有效、剩餘期間、完整簽證條件、過往同雇主任職時間或所有工作限制。
綠標不是官方核准，也不代表現在仍在招募。使用者仍須確認現行簽證條件及實際聘僱契約。

以下分數、關鍵詞、信心等級與日期邊界政策均是**本專案的保守工程規則**，不是 INZ 官方評分或官方核准機率。

## 三種標籤

| 標籤 | 意義 | 不代表什麼 |
|---|---|---|
| `likely_suitable` | 已有足夠明示資訊支持初步相容，且未發現硬性衝突 | 不保證能合法接受工作 |
| `needs_confirmation` | 聘期、雇主、工作權或文字邊界等資訊不足，應向雇主確認 | 不代表已符合條件 |
| `likely_incompatible` | 發現明確永久工作、要求超期聘僱或排除 WHV 工作權的文字 | 不會刪除職缺或自動代替人工決定 |

Profile 匹配和 WHV 評估是兩條不同判斷：符合關鍵字／地點的職缺，仍可能被標為 WHV 不相容。
系統對每筆成功正規化、同批去重後的職缺評估；預設顯示 Profile 符合者，`--show-excluded` 也可查看其他職缺及其 WHV 評估。
無效資料無法形成完整 Job，計入 invalid，不虛構 WHV 結果。

## 評分與硬性衝突

| 廣告中的證據 | 分數 |
|---|---:|
| 明示歡迎／接受 WHV | +30 |
| 明示 temporary／casual／fixed-term／contract 類型 | +25 |
| 可辨識的相容聘期 | +35 |
| 明示非永久工作且有完整任職起訖日 | +10 |
| 明確永久工作 | -70，硬性衝突 |
| 明確超過同雇主三個月限制的聘期／最低承諾 | -60，硬性衝突 |
| 明確排除 WHV／臨時簽證工作權，或僅接受公民／居民 | -70，硬性衝突 |

每項只計一次，總分限制為 0–100。硬性衝突優先，不能以正向分數抵銷。
綠標還必須同時具備已知雇主、NZ 國別、正文、明示非永久性質、相容聘期及至少 70 分；資訊含糊或矛盾不給綠標。
因此高分仍可能是黃標，分數不是唯一判定依據。

`Full time` 是工時，不是 `Permanent`。`Casual`／`Seasonal` 也不保證期限相容。
`No sponsorship` 本身不代表排除已持有效工作簽證的人。對永久工作及工作權的判斷要考慮語境、否定與替代選項，不是看見單字就判紅。

## 聘期與日期

- 只從職稱與正文中辨識與任職相關的期間／日期；不以刊登時間或 `validThrough` 推算聘期。
- 使用三個日曆月，月底採實際該月最後一天；不將三個月固定換算為 90 天。
- 支援常見英文數字／文字年、月、週、日及範圍；沒有開始日時，89–92 天／13 週視為邊界待確認，而非直接換成三個月。
- 日期支援 ISO、NZ 日／月／四位年與英文日＋月份名稱＋年；需是明示任職日期。
- 明確任職結束日在「開始日＋三個月」之前，才視為日期範圍相容；超過則為超期。
- 剛好落在三個月邊界，因起訖包含日語義可能不明，標為待確認。
- 未寫年份、日期無效、先後顛倒、只說整個雪季、最少三個月但無上限、可能延長或相互矛盾的資訊，不補成有利條件。
- 年資要求、簽證效期、試用／訓練期、申請截止日不能直接當作總聘期。
- 明確超期的最低承諾不因另一句較短契約而消失；真正的選項或模糊最低承諾仍須確認。一般彈性班表不會抵銷明確超期聘期。

範例：`2026-01-01` 到 `2026-03-01` 明確在三個月內；到 `2026-04-01` 為邊界待確認；要求固定到 `2026-05-01` 則超期。
這只是任期比較，不自動推斷廣告已過期或職缺下架。

解析器只支援已測試的常見英文措辭與日期形式，不是通用自然語言理解。遇到未支援或含糊文字應人工確認，不可將「未偵測到衝突」當成「已證明相容」。

## 理由、證據與信心

每筆評估包含 label、score、confidence、reasons、evidence、questions、tenure、規則版本／查核日期、評估日期、官方來源與原始職缺連結。
證據取自已正規化及遮蔽聯絡資料的 Job 欄位，保留短片段供回看，不加入來源沒有寫出的聘期或工作權。
信心 `high`／`medium`／`low` 只表示目前文字證據的明確程度，不是法律資格的機率。

規則超過 90 天未重新查核會顯示 `whv_rules_stale` 警告；本版保守阻止新的綠標，保留硬性衝突與待確認判斷。
這不會自動連網更新規則，也不能只為消除警告而改寫日期。

固定免責文字：僅供初步篩選，請確認現行簽證條件與聘僱契約。

## 統計、通知政策與儲存

- `whv_counts`：只統計符合 Profile 的職缺，包含綠／黃／紅三類。
- `whv_all_counts`：統計本批所有有效、去重後職缺，包含 Profile 排除與待確認者。
- `notification_policy.eligible`：符合 Profile 且 WHV 標籤在 `notification_labels` 內的筆數。
- `notification_policy.suppressed`：符合 Profile 但標籤不在通知設定內的筆數。這些職缺仍顯示，沒有刪除。

預設 Profile 選綠／黃標；若明確改標籤清單，候選統計會跟著變動。空清單表示沒有通知候選。
**候選不是待送佇列或送達數。** Phase 3 在明確要求時才將候選套用跨次去重、預覽或排隊；WHV 判斷本身不執行網路發送，見 [通知流程](notifications.md)。

Phase 2 的 run 摘要只保存 WHV 分類數、規則版本／日期與通知政策計數，不嵌入原文證據或逐筆評估。
目前 Phase 3 的 CLI 另外保存最小職缺快照與逐筆必要證據／評估；不保存完整正文。舊 run 摘要不回填，也不會被誤顯示成已做後續階段處理。
